Narrow first question

“Does this already-bounded packet need human review?”

Start with a Yes/No review question over synthetic or specifically approved packets. Do not start with permission to publish, deploy, execute a tool or make a security or financial conclusion.

Three stages

Each stage is useful even if the next one never opens.

1

Offline replay

Run a versioned fixture set without consequence. Record Sage's result, the existing deterministic route and an independent human label against the same packet digest.

Proposed
2

Live shadow

Send only separately approved, allowlisted packet fields. Record what Sage would have requested, but let the existing path continue unchanged.

Proposed
3

Braking authority

Permit one policy edition to add review or refusal. Keep every positive route, evidence gate and consequence check exactly as before.

Proposed
Non-negotiable first-live rule

The pilot can stop more work than before. It cannot permit more work than before.

Proposed

Stop conditions

  • Any credential, private path or undeclared field reaches a request candidate.
  • The response schema or accepted model edition changes without policy review.
  • A service failure falls through to a positive route.
  • False refusals exceed the accepted bound for the packet class.
  • A result cannot be joined to its packet, policy and source digests.
  • A reviewer cannot explain or reverse the route from the stored record.
