Proposed architecture

Advice inside a deterministic boundary.

The checkpoint treats Sage as one typed input to local policy. It binds the question and response to exact editions, then returns control to the rules that already govern the transition.

Five stages

The model sits in the middle, never at the end.

01 · Packet

Bound the hand-off

Name the actor, requested transition, consequence, policy edition, visible gaps and allowed content.

02 · Local

Validate and redact

Reject secrets, unknown fields, excess size, missing digests and an unapproved destination before egress.

03 · Sage

Ask one question

Receive one typed result and metadata from the declared decision kind.

04 · Local

Apply route policy

Validate the schema, model, status and policy, then choose route, review or refusal.

05 · Gate

Check the promise

Run the existing Promise Machine evidence check before any dependent transition.

Proposed

Before egress

The safest API call is the one local code refuses to make.

A future adapter accepts one closed packet schema. It canonicalises and digests the packet, checks an allowlisted policy and host, caps content and field counts, redacts declared private material and rejects credential-shaped values before any network request starts.

Proposed

Bound records

Four records make the crossing replayable.

Input

Packet record

Packet id, canonical digest, allowed field names, size and the original Shoggoth transition request.

Proposed
Policy

Question record

Policy id and digest, decision kind, exact instructions, threshold rule and permitted consequence range.

Proposed
Response

Sage record

HTTP status, validated result, model id, reported latency, received time and a digest joined to the input.

Proposed
Route

Local decision record

Selected branch, rule version, reason, review state and the Promise Machine result that actually governed the transition.

Proposed
Edition

Source record

Shoggoth commit, Levanto contract digest and all policy dependencies needed to explain the decision later.

Proposed
Unknowns

Gap record

Missing facts, parse refusals, service failures and human-review outcomes remain visible rather than becoming a false negative.

Proposed

Three local outcomes

The adapter never returns “permission granted.”

Route

A separately accepted policy may choose a low-consequence path after every local and Promise Machine gate passes.

Proposed

Review

Ambiguous, sensitive or below-policy results pause the dependent path and preserve a human decision point.

Proposed

Refuse

Invalid packets, schema drift, service errors and disallowed consequences stop the semantic route without deleting the source evidence.

Proposed

Evidence class

A Sage record stays a Sage record.

The response is recorded evidence that a named service returned a named result for a bound packet. It does not become checked, recomputed or proved evidence about the truth of that result unless a separate operation establishes that narrower claim.
