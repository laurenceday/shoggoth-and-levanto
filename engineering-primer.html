Future implementation boundary

If this goes live, the boundary is the product.

A useful adapter is not a thin HTTP wrapper. It is the closed packet, secret boundary, response validator, deterministic route, evidence record and recovery path around that call.

Proposed
Primer only

Implementation needs a new authorised build and threat review.

Current site boundary

Nothing here holds a key or reaches the service.

The published repository is plain HTML, CSS, one WebP and local Python checks. It contains no browser client, server process, environment-variable reader, network dependency, retry loop or runtime telemetry.

Before, during, after

Three gates around one request.

Before

Validate the packet

Closed schema, allowed policy digest, fixed destination, size caps, Unicode normalisation, secret scan, redaction and canonical input digest.

Proposed
During

Bound the call

Server-side credential lookup, TLS verification, fixed host, one deadline, bounded response bytes and no content-bearing retry.

Proposed
After

Validate the result

Expected status, closed result schema, accepted model id, finite numeric bounds, joined digests, deterministic route and recorded refusal.

Proposed

Published endpoint

Pin the destination; do not accept a URL from the packet.

Levanto's quickstart publishes https://sage.levanto.ai and requires authentication on every /decide call.

A future adapter should fix that origin in reviewed configuration and never follow packet-supplied hosts, redirects or proxy settings.

Metrics

Bounded counts and time

Count outcomes, failures, review load and separately scoped latency. Do not label vendor model time as end-to-end application time.

Proposed
Alerts

Alert on felt failure

Trigger on positive fall-through, unjoined records, drift refusals, sustained service loss and review backlog—not on one noisy model score.

Proposed

Proof before deployment

  • Valid, malformed, oversized and credential-bearing packet fixtures.
  • Every documented HTTP failure plus timeout, redirect and oversized response.
  • Unknown, missing, duplicated and non-finite response fields.
  • Policy and model drift with no permissive fallback.
  • Redaction and retention review against the exact data classes.
  • Differential replay proving the existing gate never becomes less strict.
